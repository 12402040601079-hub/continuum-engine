# Continuum Engine - Database Schema Design

This document details the MongoDB collections, field specifications, indices, and validation rules for **Continuum Engine**.

---

## 1. Collections Overview
We use MongoDB as our primary persistent store. The schema defines two main collections:
1. `session_snapshots`: Caches uncommitted form wizard state to prevent data loss.
2. `telemetry_logs`: Records client crash telemetry and chunk load 404 failures.

---

## 2. Collection: `session_snapshots`

### 2.1. Schema Specification
Each document in `session_snapshots` contains the state of a user's multi-step wizard application.

| Field | Type | Description | Required |
| :--- | :--- | :--- | :--- |
| `_id` | String | Unique session token (UUID v4) generated by the client or server. | Yes |
| `user_id` | String (Nullable) | Identifies the authenticated applicant (if logged in). | No |
| `client_version` | String | The running semantic version of the client app at capture (e.g., `1.0.0`). | Yes |
| `current_step` | Integer | The active step index (1 to 4) when the snapshot was saved. | Yes |
| `form_data` | Object | Nested key-value map containing the user's form inputs. | Yes |
| `last_saved_at` | DateTime | Timestamp of the last successful snapshot update. | Yes |
| `expires_at` | DateTime | Expiration timestamp (used for MongoDB TTL indexing). | Yes |
| `is_recovered` | Boolean | Flag indicating if this session has been rehydrated post-crash. | Yes |

```json
      "_id": {

        "description": "Must be a unique string (UUID v4) session token."

      "user_id": {

      },
      "client_version": {
        "bsonType": "string",
        "pattern": "^[0-9]+\\.[0-9]+\\.[0-9]+$",
        "description": "Semantic version format (e.g. 1.0.0)."
      },
      "current_step": {
        "bsonType": "int",
        "minimum": 1,
        "maximum": 4,
        "description": "Must be an integer between 1 and 4 inclusive."
      },
      "form_data": {
        "bsonType": "object",
        "description": "Dynamic key-value inputs mapped by step fields."
      },
      "last_saved_at": {
        "bsonType": "date",

      },

```

### 2.3. Indexing Strategy
- **Primary Key:** Unique index automatically created on `_id`.
- **TTL Index:** A TTL index on `expires_at` with `expireAfterSeconds: 0`. This automatically purges expired states from the database (e.g., set to expire 48 hours after creation).
- **User Index:** Non-unique index on `user_id` to quickly look up active snapshots for returning authenticated users.

## 3. Collection: `telemetry_logs`

### 3.1. Schema Specification
Each document in `telemetry_logs` represents a dynamic asset chunk load error captured on the client side.

| Field | Type | Description | Required |
| :--- | :--- | :--- | :--- |
| `_id` | ObjectId | MongoDB unique document identifier. | Yes |
| `session_id` | String | Reference to the `_id` in `session_snapshots`. | Yes |
| `client_version` | String | Client version that experienced the failure. | Yes |
| `target_asset_url` | String | URL of the dynamic asset chunk that failed to load (returned 404). | Yes |
| `user_agent` | String | Client browser user agent string. | Yes |
| `timestamp` | DateTime | The exact time of the caught exception. | Yes |
| `error_message` | String | Description of the caught error. | Yes |
| `stack_trace` | String (Nullable) | Full Dart/Javascript error stack trace if available. | No |

### 3.2. JSON Schema Validation Rules
```json
{
  "$jsonSchema": {
    "bsonType": "object",
    "required": ["session_id", "client_version", "target_asset_url", "user_agent", "timestamp", "error_message"],
    "properties": {
      "session_id": {
        "bsonType": "string",
        "description": "Reference session ID."
      },
      "client_version": {
        "bsonType": "string",
        "pattern": "^[0-9]+\\.[0-9]+\\.[0-9]+$",
        "description": "Semantic version format (e.g. 1.0.0)."
      },
      "target_asset_url": {
        "bsonType": "string",
        "description": "URL of the dynamic JS chunk that returned 404."
      },
      "user_agent": {
        "bsonType": "string",
        "description": "Client browser user agent."
      },
      "timestamp": {
        "bsonType": "date",
        "description": "Datetime representing error occurrence."
      },
      "error_message": {
        "bsonType": "string",
        "description": "Descriptive message of the failure."
      },
      "stack_trace": {
        "bsonType": ["string", "null"],
        "description": "Stack trace snippet."
      }
    }
  }
}
```

### 3.3. Indexing Strategy
- **Time-Series Indexing:** Index on `timestamp` (descending) to optimize dashboards pulling recent failure rates.
- **Compound Index:** Compound index on `{ client_version: 1, timestamp: -1 }` to filter logs by deployed version and order chronologically.
